# 下一阶段工作与验收

[返回首页](../README.md)

优先完成影响实际运动的低速执行质量；空地坐标与接口、融合定位复核可以并行。这里列的是后续最小工作范围，不意味着这些试验已执行，也不要求新增运行框架。

## P0 固定一次实验的实际版本

**目的：让问题和结果能归属到同一套源码、固件、参数。**

确认本次实际板卡固件，区分3849实测基线与0852安装记录；记录driver模式、输出上限实际值、轮径/计数/符号、电池及地面。0852新增0x18目前未由我方ROS driver配置，不能用host的600‰字段推定实际输出上限。

记录启动入口、加载文件和运行参数，重点避免三类混淆：普通sensor_root与在线冻结配置、默认DWA容差与现场动态修改、默认PWM配置与显式body_speed。已有工具和manifest足够使用，不需要新增版本管理服务。

本仓库根 `src/`、`tools/` 是我方候选；选定依赖在 [reference/Slicer_Workspace](../reference/Slicer_Workspace/)，3849 在 [reference/field_verified_3849abee](../reference/field_verified_3849abee/)，来源记录在 [reference/provenance](../reference/provenance/)。队友 [643a704 固定提交](https://github.com/20DCYy06/potato-ugv-online-navigation-radio/tree/643a704c5fa042b5e9f08d3c37ddad3a38e8b56a) 的 Gmapping + B 样条 + TEB、FKIE 与我方实测 odom + GlobalPlanner + DWA / 新 online 候选分别记录，不能因为共享依赖就当成版本一致。实验前明确选择一个工作区，避免混编、同名包覆盖或双启动；迁移时逐项确认 TF、传感器、串口和速度话题的唯一所有者。

## P0 低速起转与换向质量

**目的：让车能持续跟随导航真正使用的低速，而非只保证方向变对。**

| 最小对照 | 观察项 | 可以缩小到哪里 |
|---|---|---|
| 同负载、少量低速档的0x10恒向/换向 | 四轮目标、编码器速度/计数、PWM、起转延迟和近零时间 | 轮速内环与执行侧是否自身存在迟滞/脉冲 |
| 0x16恒向/换向 | body目标/gyro、实际轮目标、yaw I与必要的轮I | 车体外环到轮内环衔接是否造成额外延迟 |
| 小wz及非零vx曲线 | 巡航中小角速修正、左右对称性 | 纯转结果能否覆盖导航工作区间 |

继续使用Guard/Mux/Watchdog。两模式目标生成不同：0x10的host几何与0x16的车体几何/反馈项不等价，不能只输入相同Twist便称严格对照。内部量缺失时只补必要诊断，不能从25Hz遥测推造更高频内部状态。

建议每个关键方向至少重复三次，先用共同口径记录稳定起转延迟、目标/反馈积分比、稳定误差与停顿占比，再约定可接受范围。平均速度接近目标不能掩盖先停后冲。只有证据支持内环死区/摩擦补偿时才标定前馈，不继续盲加最低PWM、翻旧积分或成组调参。

## P0 短直行与停车精度

**目的：区分底盘速度响应、轮尺度、融合定位和到点判据。**

同一车体参考点测量完全停稳后的位移；每次明确起点是否重置、尺子是否移动。先比较少量不同速度的短直线，记录横偏与航向，再做现有单目标导航。

一份同步记录覆盖开始静止、完整运动和结束静止，至少包含：

- 原始目标/Action状态、DWA raw、Guard输出与理由、Mux输出/来源；
- driver发送与ACK、MCU目标、四轮速度/计数/PWM、gyro和状态；
- LIO、wheel、融合odom、TF与实际参数；
- 外部距离/角度或可同步的视频，以及电池/地面条件。

以首个真实接收的零目标为界，分开软件零速传递、编码器/gyro停止和物理余程。不能用最终一小段静态bag补过去轨迹，也不能用Action成功替代尺量。重复数据稳定后，再决定是调整轮速标定、内环、EKF响应还是到点容差。

## P1 定位、感知与在线候选

| 工作 | 最小完成依据 | 不能由此保证 |
|---|---|---|
| LIO+wheel融合 | 明确掩码/协方差/时间戳；运动与静止时TF唯一；与外部尺量/量角比较 | 单次无跳变不证明长期无漂移 |
| LIO失效行为 | 原链路停止自主输出，恢复定位后旧目标/坐标处理清楚 | wheel vx不能单独提供失效航向 |
| 低障碍感知 | 固定物在原始回波、body cloud、过滤、scan、Costmap各层连续可追踪 | 一个箱体成功不代表杯子/门槛都可见 |
| D455深度候选 | 标定安装外参、CameraInfo/时间，检查地面误标、物体移走清除和断流 | 合成几何测试不证明室外或低反射表现 |
| 在线Gmapping | map→odom与odom→base_link不冲突；地图连续、目标frame正确；Jetson负载可接受 | 建图运行不等于长距离导航验收 |
| 全局路径问题 | 固定目标、同刻Costmap与参数重现失败，区分占用、未知、窗口和提取 | 一次NO PATH不能解释整段停滞 |

先静止检查，再短距离单场景；低速执行未收敛前，不通过放宽Guard或提高导航角速掩盖问题。

## P1 空地单目标与真实GNSS

飞机侧可先学习现有消息、做已知点坐标计算和无运动通信。车端补最小目标适配，利用标准Action反馈和取消，不引入新任务状态机。

先处理 [接口指南](03_air_team_guide.md) 中的现状：receiver 默认写 `slicer_navigation/config/waypoints.yaml`，队友在线 patrol 默认读 `slicer_navigation_without_mapping/config/waypoints.yaml`；收点不自动运行，两边尚未接到我方 `/ugv/move_base` Action。明确文件去向和任务触发，验证原巡航对 `/move_base`、TEB 话题的依赖，再决定保留哪段现有实现；不要用双启动两套导航来拼接任务。

GNSS按“接收机原始数据 → 真实差分 → 质量/时间 → 公共原点与基准 → ENU/map配准 → 车体参考点”逐项验收。先确定是否确实需要GNSS参与任务坐标；局部LIO导航本身不依赖RTK，GNSS软件存在也不自动代表全局定位闭环成立。

空地单目标需要同时证明：飞机发出、车端收到、坐标解释一致、任务接受/拒绝、Action结果映射、飞机收到结果以及取消生效。之后才扩展多点或比赛全流程。
