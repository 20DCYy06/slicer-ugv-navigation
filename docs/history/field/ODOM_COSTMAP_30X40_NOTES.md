# 将来覆盖30×40m：固定全局与滚动全局的待验证差异

本轮只交付12×12m滚动测试profile，不实现固定地图、探索器、SLAM或新的导航框架。以下是下一阶段选型需验证的差异；局部DWA/Guard可以继续复用。

| 项目 | 固定全局Costmap | 当前滚动全局Costmap |
|---|---|---|
| 边界和坐标 | 边界固定在odom中，必须选origin、尺寸和机器人/膨胀余量；默认origin=(0,0)可能把起点放在边界。无StaticLayer也可由scan在线更新。 | 窗口随机器人中心移动。12m约各轴±6m；即使窗口改30×40，也只是车附近±15/±20m，不能从任意位置覆盖全赛场。 |
| 目标范围 | 目标及规划路径须在固定边界内；先核对赛场坐标相对odom的范围。 | 远目标可能在当前窗外，扩大窗口或分段目标的必要性要实测；本轮不实现分段任务层。 |
| 地图历史 | 固定边界内已观测状态通常保留，动态旧障碍仍需被有效射线清除；离开传感范围后不能自动认为信息仍新鲜。 | 重叠区域可保留，滚出区域被丢弃，重访后需重新观测。不能把它当全场持久地图。 |
| 未知区域 | 大窗口不会让远区可见；是否允许全局经过unknown须明确，否则未观测远目标可能无路径。 | 本轮允许GlobalPlanner经过unknown，但保留unknown格，局部与Guard仍拒绝未知/占用/越界运动。不能保证未知场地有路。 |
| 感知和障碍更新 | 仍只有当前雷达可观测区域被更新；需检查远处历史障碍、遮挡和清除行为。 | 同样受3m标记/最多4m清除及实际scan范围约束，窗口扩大不增加传感覆盖。 |
| odom漂移 | 大范围旧障碍与新观测可能错位；固定窗口不校正漂移。 | 窗口滚动也不校正漂移；需测长路程与重访的一致性。 |
| 计算/传输 | 0.05m下30×40为600×800=480,000格；规划及发布成本应测。 | 同尺寸格数成本相同，另有移动原点/重访影响。当前12×12为57,600格，扩大至30×40是8.33倍格数。 |

按当前全图4Hz发布，仅OccupancyGrid的data区约从0.23MB/s增至1.92MB/s，未计协议、其他话题和bag压缩。需要测实际CPU、规划周期、时延及资源占用，不能从格数直接宣称平台性能足够。

将来的最少对比项：

1. 从预期场地起点到边缘/角落，验证目标是否在栅格内、路径是否有足够边界余量。
2. 离开传感范围后重访同一障碍，比较历史保留、未知格、旧障碍清除及重新出现。
3. 同一个远目标下放入/移走障碍，检查仍是同一Action、重规划是否及时、局部停止/绕行与取消是否有效。
4. 长路程实际位移/航向、地图重访错位，以及相应CPU/话题延迟；固定/滚动都不能以软件模型代替这些实测。

两种方案的比较不等同于地图定位方案重构。本轮未修改融合、固件、控制接口或恢复策略。
