# 给 Codex：先调通 MCU 轮速闭环，再验收直行和停车

**目标：** 在现有 C30D MCU 内把低速轮速闭环调到可用，依次解决低速不起转、直行跑偏、停车不准。交付最小源码修改和实车对照结果；不能以测试条目数量代替实车结果。

**架构：** 保持现有 ROS1 Noetic、Guard/Mux、串口协议和 MCU PI 控制边界。台架阶段直接复用现有 Chassis 串口接口隔离导航影响，正常地面导航恢复 Guard/Mux/Watchdog。速度闭环留在 MCU，不搬到导航器，不新增运行管理框架、任务状态机或自动恢复系统。

**技术栈：** STM32 C、现有固件构建脚本、Python Chassis、现有 ROS1 导航。

**需求依据：** 用户本轮明确要求“优先把现有MCU轮速闭环调通，解决低速不起转、直行跑偏和停车不准，给出最小修改和实车验证方法，别再把外围修复放在前面，也别加新框架”。本任务单替代上一版的实施优先级；历史报告仍可作为证据索引，不能继续照旧顺序施工。

## 3. 第一项交付：用最少直接串口对照选定补丁

- [ ] 先离地，从完全静止开始，对照同一板卡上的 0x11 和 0x10。避免键盘自动重复决定指令持续时间；入口按固定周期刷新，并有明确段长、结束零及关闭清理。复用现有串口独占方式。
- [ ] 默认建议20 Hz发送、每段3 s，段前停稳，段后至少观察2 s；这些是采样设置，不增加运行时框架。遇到当前故障立即保留结果结束，不自动清错续跑。
- [ ] 先用已知可动的 PWM 档作正对照，再试接近当前闭环故障前输出的70‰。若两者响应不同，在区间内做少量人工选择的短段，分别测静止起转与已转动后的维持输出。不要一开始全范围盲扫。
- [ ] 0x10首先测全轮+19直行、正/反向±19纯转，随后100参考点。需要定位某轮时，只对该轮发送非零，其他轮置零；复用四轮接口，不引入新模式。负向直行只需台架验证，不因此放开地面导航倒车。
- [ ] 配置顺序必须正确：0x11进入direct后清除configured；转入0x10前先停零，再调用configure(encoder_signs)，确认ACK及configured遥测。现有fault按既有Motor OFF/HELLO流程人工清理，不自动反复复位。

现有端口关系已确认：**A右后、B左后、C右前、D左前**。在当前符号配置下：

| 测试意图 | 0x11电气PWM，ABCD | 0x10轮速目标，ABCD |
|---|---|---|
| 前进 | [P,-P,P,-P] | [v,v,v,v] |
| 左转 | [P,P,P,P] | [v,-v,v,-v] |
| 相反方向 | 上述取反 | 上述取反 |

0x11阶段反馈未应用已配置编码器符号，比较时用raw counts按确认的方向归一化，不能直接把其显示速度当成0x10的同符号反馈。0x20标定仍走旧桥写法，**本轮不要用它的曲线给新桥配前馈**。

最少记录现有observe输出：主机发送时间/序号/目标、MCU接受序号与tick、原始计数、实际速度、duty、故障、电压；配合车轮标记视频确认轮是否真实转动。遥测时间间隔不是每次控制dt，不能混写。现有字段已足够开始这轮判断；仅当首因无法区分而直接妨碍修复时，补一个触发轮/子原因，别先重做诊断协议。

**本项结束必须给出一个控制结论：** 是非零未获接受、输出尚不足起转、轮已转而反馈不对、方向错误，还是输出及反馈正确但控制振荡。证据不足时只补能区分这几个分支的那一项测量。

## 4. 第二项交付：按数据做最小 MCU 控制补丁

按以下顺序选择需要的改动，不要求全部实现：

1. **先处理符号与单位的确定错误。** 保留原始counts/s；多圈核对编码器每圈计数、轮周长和方向后，才把60000 counts/rev、85 mm轮径等暂定量当成物理速度依据。不能用软件显示的mm/s反过来自证换算正确。
2. **先改前馈，再调必要的PI。** 用起转、维持、19附近与100参考点共同选择简单参数。若统一参数能满足四轮，不加分轮表；只有重复数据表明轮/方向差异才增加少量分轮或分方向参数。B5高速度点积分抵消较大前馈，与19点起转不足可以同时存在，不能把全区间FF一起盲目加大。
3. **确有静摩擦差异才加有限启动补偿。** 明确补偿幅度、最多持续多久、检测到转动后如何退出。零命令立即清除补偿和积分；稳态微小误差不能不断重触发强脉冲。保持在现有control()内实现，不新建通用状态机。
4. **同时修正失速判断与起步过程的失配。** 依据实测起转时间、实际输出和正常低速计数，确定何时计时、反馈阈值、允许持续时间。450 ms可以变，4%也可以变，但须说明依据；正常起步应有机会完成，持续无反馈仍须在明确有限时间内停止。只延长时间让积分慢慢堆大，不算已解释根因。
5. **检查低速退出、反向及降速。** 用真实C函数确认积分不会让旧方向持续输出，零命令不被斜率或补偿拖延；先停再反向的主机指令不等于车轮已物理停稳。只修出现证据的问题，不顺手重构控制器。

0x10当前有效输出上限960/1600=600‰，保留这条已有软件边界；它不是硬件额定值保证。也不要因一路CCR恒为1600就误判差分输出达到100%。本轮不靠提高上限解决起转。

**离线验证绑定实际待刷源码和实际生成参数：**

- [ ] 重现原版19低反馈下的积分/输出/失速时序，再验证候选在“反馈于实测启动时刻出现”和“反馈始终不出现”两种输入下的差异。前者检验算法逻辑，不能当成电机已能启动。
- [ ] 验证10/20/30 ms及混合dt下积分与计时使用真实dt；保持已有调度超时语义。
- [ ] 验证零、单轮零、变号、饱和恢复、配置丢失、fault、使能关闭、500 ms通信超时后输出及积分/补偿清理；正常0x10输出不超过960 ticks，原桥极性不回退。
- [ ] 对实际源码编译、运行现有native/bridge模拟外设用例及新增控制用例。旧runner硬编码了旧源码哈希、KI和450边界，需要保留历史结果并适配候选入口/新断言；不能为了显示绿色继续测试旧main，也不能删除失败断言后宣称问题已修。
- [ ] 输出可复现命令、所测源码/参数哈希与结果；软件输入回放只证明实现符合设计，不能替代实车起转和停车。

## 5. 第三项交付：同一轮实车采样分阶段验收

电池充好后记录静态及带载电压；避免把一次电压读数写成低电量归因。以下是分阶段放行，前项失败先修对应层，不继续做大量导航试验。

| 阶段 | 最少操作 | 通过依据与失败分流 |
|---|---|---|
| 无运动检查 | 核对镜像/回读；0x12配置、configured、四零；断开发送后的Watchdog | 协议与停零路径符合预期。这一步不证明动力闭环通过 |
| 离地低速闭环 | +19直行、±19纯转，每类从静止重复3次；补100参考点，必要时逐轮 | 四轮均能可靠起转，方向正确，不再重现保护误杀；报告启动延时、速度误差、峰值、duty和故障 |
| 地面直行与低速自转 | 先短距离恒定轮速验证，再做0.5/1 m直行；使用慢/快两个已记录的速度设置 | 对比左右真实轮速、横偏、航向与重复性；纯侧方目标不作为非全向车基本运动验收 |
| 停车与导航 | 完整Guard/Mux/driver链下做0.5 m目标，慢/快各3次；通过后补1 m | 同时对照目标位置、SUCCEEDED瞬间与最终停稳位置，不能只看Action状态 |

建议首轮量化目标：稳定段每轮速度误差不超过max(3 mm/s,目标10%)；0.5 m导航停稳纵向误差先以±5 cm、横偏≤5 cm作为工程目标。**这些是待实测检验的建议目标，既不是已证明能力，也不允许为了达标修改测量口径。** 同时报告1 m横偏、航向变化、起转时间和停零后余程，不用平均数掩盖单次失败。若达不到，指出具体哪一层限制，而不是笼统写“硬件问题”。

直行不准按下列最短路径分流：

- 同目标但左右实际轮速不一致：先修相应轮的反馈换算、前馈/PI或输出路径。
- 编码器轮速一致但车仍偏：核对轮周长、负载、打滑、轮轴/机械和外部航向；不能让导航长期纠偏掩盖原因。
- 轮明显在转而编码器不对应：定位到编码器/接线/计数配置，不继续调PI。

停车采样必须覆盖从起步到完全停稳的全过程，固定同一车体标记。至少同步：raw/Guard/Mux后的指令、串口0x10及ACK、MCU目标/速度/计数/duty、odom/TF、目标与Action状态、外部距离/视频。分别标出首次零指令、MCU输出归零、轮停止、车体停稳；主机与MCU时钟做关联，不假设天然同源。

- 零指令迟到或尚有非零输出：修对应传递/控制环节。
- MCU输出归零后轮/车仍动：量化余程。当前源码写双零，实际是滑行还是制动要核对板卡真值表/必要波形，不能凭函数名断言。常规减速可按实测调整；未经电桥依据不擅自改主动制动，也不能延迟立即停零路径来伪装停车改善。
- 车已停但定位继续变：查运动定位/同步，不能继续增加PWM补偿。
- SUCCEEDED时定位已入容差而物理距离不对：核查目标变换、定位与容差。若当时确用0.15 m容差，理想直线0.5 m目标约0.35 m即可进入位置容差，这可解释“0.3 m多成功”的一种情况，但须当次参数及位姿佐证。闭环稳定、定位可信后再收紧到点容差，与±5 cm验收目标匹配；不能只把容差改小就宣称停车已修好。

不使用3.806秒末段静态bag补写过去的运动曲线，不用两套绝对里程计坐标差直接判定尺度/TF错误。

## 6. 软件仍不能解决时，定位到可检查的部件

只有软件指令、实际写出和计数证据不足以解释时，再补对应电气测量：CCR正确但引脚不对，查定时器/复用/使能；输入正确但桥输出不对，查电桥或供电；电机转而计数不对，查编码器链；输出到达电机且反馈可信、仍在合理负载下不转，查电机/减速器/机械。已有WASD成功支持电机在部分条件下可工作，不能排除低速摩擦、方向差异或带载供电问题。

## 7. 最终交付格式

1. **实际解决了哪个运动问题：** 起转、左右速度一致性、停车分别写结果，不把三者合并。
2. **最小diff与参数表：** 原值、新值、实测依据、预期作用；未采用的复杂设计不实现。
3. **可复现离线命令、候选构建与回读身份。** 如调整了旧测试预期，解释对应控制行为为何有意改变。
4. **用户可逐条执行的现场命令和记录表。** 每条说明离地/地面、速度/PWM、段长、如何结束；不提供运行后自动串行运动的大脚本。
5. **实车数据与结论边界。** 未测就写未测；若受硬件限制，给出定位证据、缺少的唯一关键观测和对应部件，不再以“增加更多日志/保护”代替处理电机控制问题。
