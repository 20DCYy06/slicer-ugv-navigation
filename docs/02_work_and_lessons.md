# 已做工作与问题复盘

[返回首页](../README.md)

项目的主要贡献是把成熟算法、队友底盘与通信基础接成一条能检查、能复现实验的 UGV 链路，并针对现场证据做最小修正。下面将“代码修复”“参数/集成改善”“有限现场成功”和“尚未解决”分开。

队友的 [potato-ugv-online-navigation-radio（643a704 固定快照）](https://github.com/20DCYy06/potato-ugv-online-navigation-radio/tree/643a704c5fa042b5e9f08d3c37ddad3a38e8b56a) 展示 Gmapping + B 样条 + TEB 与 FKIE 通信链；我方现场复盘主要对应 odom 下的 GlobalPlanner + DWA，新增 online 是另一条待验收候选。共同使用 FAST-LIO、EKF、底盘和通信组件不代表版本、参数和验证结果一致，双方的成果不能互相替代。

## 现场现象并不只有一个原因

| 现象 | 查明的机制或边界 | 已做处理 | 当前结果 |
|---|---|---|---|
| 导航重启后完全不动 | Mux startup held，未交还自动控制权 | 明确状态观察与一次性交接入口 | 已识别的操作原因；与后续低速滞转分开 |
| 早期直行夹带微小角速后动力突变 | 原PWM映射在零/非零角速分支不连续；新函数曾未进入实际driver | 受控driver调用链接入连续映射；后续主线改为0x16 | 确定代码问题得到处理；不能据此解释所有位移误差 |
| 侧方/纯转目标被反复拒绝 | 非全向底盘；TEB软前进偏好仍可产生负vx，和严格禁倒车不一致 | Guard不再把非法倒退改成纯转；主线采用DWA | 契约更清楚；不宣称TEB只改一个参数即可硬禁倒车 |
| 车停了，Action还迟迟不结束 | 部分记录中MCU/轮速已停，融合wz仍拖尾 | 同bag回放后仅调整Q(wz) 0.02→0.2 | 响应改善；静止噪声有代价，物理停车距离另验 |
| 0.5m目标短走仍SUCCEEDED | 到点容差较宽，融合估计与物理位置也需区分 | yaw容差0.25→0.12、xy0.15→0.10的单变量对照 | 历史实测约37→41.5cm，有改善，未达到精确50cm |
| 低角速度收到却不持续运动 | 目标/ACK正常时轮速/gyro间歇近零；部分历史还有单轮异常平台 | 从导航外围转向MCU外环与轮内环排查 | 未唯一归因为硬件；低速连续跟随仍未验收 |
| 交替转向受旧方向影响 | MCU yaw积分在目标换向后仍反对新请求；首版补丁漏掉幅值过小情形 | 3849在真正纯转换向且积分冲突时一次清yaw I | 受测±0.08rad/s方向功能恢复；跟随比例仍不足 |
| NO PATH或oscillation | 曾有目标占用、路径提取异常、TEB/Guard不一致、低速执行不足等不同事件 | 按目标、Costmap、规划、命令、MCU反馈分层观察 | 不能统一归罪GlobalPlanner或底盘；部分提取问题仍需固定输入复现 |
| 水杯/门槛等低障碍不稳定 | 原始回波、LIO筛点、投影高度、自身过滤和清图需区分 | 分层静止采样，新增深度候选 | 低障碍普遍可靠检测尚未通过；不能靠改栅格尺寸补出未测到的点 |

早期0.5m/1m超调、后来的短走、EKF拖尾和纯转滞转不是同一组实验。软件SUCCEEDED只说明规划器依据当时反馈满足了配置条件；它不会自动证明尺量精度、真实制动或轮速标定正确。短静态bag也不能补出过去的运动曲线。

## 已有现场成果应如何表述

- **短目标导航**：有直行、左右转与二维目标自行完成的历史记录，但容差、横偏和低速修正仍影响精度。
- **遇人停车再续行**：有同一Action内停车、障碍离开后续行成功记录。这与主动绕行是不同能力。
- **一次固定箱体绕行**：约30cm宽、40cm高箱体，用户确认无接触、无人工干预并自停。它支持一次场景成功，不涵盖低门槛、透明物或动态复杂障碍。
- **10m试验未到点**：约141.2s后ABORTED，软件目标残差约1.124m。用户后续明确末段停在空地、没有接触物体；旧报告中目标附近门槛的描述不能用作“车被顶住”的解释。
- **3849交替方向试验**：六段都形成请求方向的净转动；MCU角速积分约为请求的30%–44%，仍有约1.2–1.4s反向持续起转迟滞。角速积分不是外部量角，也不是完整导航测试。

历史记录见 [EKF现场](history/field/EKF_IMU_FIELD_20261027.md)、[精度与箱体绕行](history/field/NAV_PRECISION_FIELD_20261027.md)、[10m记录](history/field/INDOOR_10M_RESULT_20261028.md)。这些保留原文与当时判断；本文明确纳入后续“末段无接触”的用户补充。3849独立复核摘要见 [证据索引](06_evidence.md)，对应源码与身份材料放在 [3849 对照目录](../reference/field_verified_3849abee/)。原归档软件检查材料位于 [archive_20261030](../evidence/archive_20261030/)，不是本次目录整理新增的实车验证。

## 哪些做法已经证明有用

先核实实际加载的文件、模式和版本，再调参数；源码里有函数不等于实车执行了它。先看原始命令是否到达，再看轮反馈、gyro、LIO及外部测量，能避免把所有“不动”都当作保护触发。

同时记录原始目标、Guard/Mux输出、driver发送、MCU ACK/反馈、定位、TF和Action结果，可以区分“没发出去”“发到但未执行”“执行了但反馈判据不同”。保留失败记录与单变量对照，比大量逐档PWM试探更容易缩小问题。

下一步仍以底盘低速质量为主线；融合、在线地图与空地接口可做不依赖运动的工作，避免等待底盘时停下所有协作。
